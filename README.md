## Project Overview

Financial institutions process thousands of card transactions every day. Monitoring suspicious transaction behavior is important for reducing financial losses, improving customer trust, and supporting fraud investigation teams.

This project demonstrates a practical Data Analyst workflow by transforming raw transaction data into meaningful business insights through data cleaning, exploratory data analysis, SQL-based KPI analysis, and data visualization.

The goal is not to build a predictive machine learning model. The focus is on understanding historical transaction behavior, identifying fraud trends, and presenting findings that support operational decision-making.

## Business Problem

Fraud monitoring teams need structured reporting to understand where fraud is occurring, which transaction patterns are riskier, and which operational metrics should be monitored regularly.

### Business Questions

- What percentage of total transactions are fraudulent?
- How does fraud vary across transaction locations?
- Are specific transaction hours associated with higher fraud activity?
- How do transaction amount and device trust score relate to fraudulent behavior?
- Which KPIs should fraud operations teams monitor?

## Project Objectives

- Prepare and clean transaction data for analysis.
- Validate data quality and check for missing or duplicate records.
- Explore transaction behavior using descriptive statistics.
- Identify fraud-related trends through exploratory data analysis.
- Use SQL queries to calculate business KPIs.
- Create clear visualizations for stakeholder reporting.
- Translate analysis results into business insights and recommendations.
